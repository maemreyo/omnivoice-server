=== PUNCTUATION COMPATIBILITY VERIFICATION ===

add_punctuation() function (OmniVoice/omnivoice/utils/text.py:207-219):

```python
def add_punctuation(text: str):
    """Add punctuation if there is not in the end of text"""
    text = text.strip()
    
    if not text:
        return text
    
    if text[-1] not in END_PUNCTUATION:
        is_chinese = any("\u4e00" <= char <= "\u9fff" for char in text)
        text += "。" if is_chinese else "."
    
    return text
```

Behavior:
1. Strips whitespace (idempotent with ASR .strip())
2. Returns empty string unchanged
3. Checks last character for existing punctuation
4. Adds "。" (Chinese) or "." (other) if missing
5. Returns unchanged if punctuation already present

Compatibility with contract:
✓ Expects plain str input (contract guarantees this)
✓ Handles empty string gracefully
✓ Idempotent .strip() (safe even if ASR already stripped)
✓ No assumptions about ASR output format
✓ Works with any language (Chinese detection built-in)

=== DOUBLE-PUNCTUATION PREVENTION ===

Scenario: What if ASR backend adds punctuation?

Current transformers backend:
- Whisper ASR may include punctuation in transcription
- Example: "Hello world." (with period from ASR)
- add_punctuation() checks text[-1] not in END_PUNCTUATION
- If period present, no additional punctuation added
- Result: "Hello world." (unchanged)

Contract requirement:
- ASR backends MUST NOT add punctuation during normalization
- Rationale: Preserve control via preprocess_prompt flag
- If preprocess_prompt=False, no punctuation should be added
- If ASR adds punctuation, user cannot disable it

Risk mitigation:
✓ Contract explicitly forbids ASR punctuation addition
✓ add_punctuation() is defensive (checks before adding)
✓ Separation of concerns: ASR = raw text, preprocessing = formatting
