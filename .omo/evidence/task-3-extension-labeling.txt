## CLASSIFICATION FRAMEWORK

Based on temp.log verdicts and upstream OmniVoice documentation:

**UPSTREAM-NATIVE** = Feature exists in k2-fsa/OmniVoice model, server passes through
**SERVER-ONLY** = Feature implemented by omnivoice-server wrapper (HTTP, profiles, etc.)
**AMBIGUOUS** = Documentation unclear about origin, could confuse users

**Server-only features:**

**Documentation status:**

```markdown
## Features

### Upstream OmniVoice Capabilities (Pass-Through)

- Non-verbal symbols inline in text ([laughter], [sigh], etc.)

- Generation parameters (speed, num_step, temperature, etc.)

### Server-Only Extensions
- OpenAI-compatible HTTP/REST API
- HTTP streaming transport with sentence-level chunking
- Persistent voice profile storage and management
- OpenAI-compatible preset names (alloy, nova, etc.)
- Bearer token authentication
- Health and metrics endpoints
- Concurrent request handling
- Audio format conversion (tensor → WAV/PCM)
```

This structure makes it immediately clear what comes from upstream vs what the server adds.
